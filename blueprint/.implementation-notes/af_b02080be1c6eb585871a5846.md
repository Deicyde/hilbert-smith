A structure `HSP.Corner.StandingData` with the data fields (p, a, χ, T with its metric, compactness, nonemptiness, the action, freeness, isometry, n, R, s and the two inequalities), plus derived definitions in the same namespace: `Z₀`, `Z`, `B m`, `Y m`, `A m`, `yPlus`, `yMinus`, and the round metric on `OnePoint (EuclideanSpace ℝ (Fin n))`. Interface decision 1 puts all of these in this one article; if the Lean side prefers one declaration per definition, they are abbreviations attached to the structure, not separate articles.

$C_p$ is now additive (`ZMod p`, interface decision 4), freeness is `∀ c t, c +ᵥ t = t → c = 0` (or `c • t` with `Multiplicative`, whichever the categories chapter uses for the action). Isometry via `IsIsometricSMul` (Mathlib, Topology/MetricSpace/IsometricSMul.lean). Stereographic projection: `stereographic'` and `onePointEquivSphereOfFinrankEq` in Mathlib (Geometry/Manifold/Instances/Sphere.lean, Topology/Compactification/OnePoint/Sphere.lean); the round metric is the angle `InnerProductGeometry.angle` pulled back along that equivalence (angle name unverified in this Mathlib version).

Nonemptiness of $T$ is used by the component projection (relabelling equivalence needs $T\times\{y_+\}$ nonempty). The local-data chapter does not yet prove that the control space is nonempty; requested in the c2-corner report.
